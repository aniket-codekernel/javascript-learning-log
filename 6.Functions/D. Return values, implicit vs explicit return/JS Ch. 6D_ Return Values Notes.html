Chapter 6, Section D: Return Values — Implicit vs Explicit Return

1. What return does

return sends a value out of a function, back to wherever it was called. The moment return runs, the function stops immediately — nothing written after it runs.

function add(a, b) {
  return a + b;
  console.log("this never runs"); // unreachable
}

const result = add(2, 3);
console.log(result); // 5

2. No return → undefined

function greet(name) {
  console.log(`Hi, ${name}`);
  // no return
}

const result = greet("Aniket"); // prints "Hi, Aniket"
console.log(result);            // undefined

console.log only prints to the screen — it does not hand a value back to the caller. Without return, the function still runs fully, but whatever called it receives undefined.

Key distinction: return and console.log are unrelated jobs.

Job
console.log(x) Shows x on the screen (for you, the developer)
return x Sends x back to the caller (for the code to use)

3. Explicit return

Used in:

  • all regular functions
  • arrow functions that use { }
function square(n) {
  return n * n;
}

const square2 = (n) => {
  return n * n;
};

You write the word return yourself. Required whenever the function body is wrapped in { }.

4. Implicit return (arrow functions only)

const square = n => n * n;

No { }, no return keyword. The value of the single expression is automatically sent back.

Rule: implicit return only works when —

  1. there are no curly braces, and
  2. the function body is a single expression
const double  = n => n * 2;       // ✅ implicit return, works

const double2 = n => { n * 2; };  // ❌ braces added, but no "return" written
                                   //     → returns undefined

Common bug: adding { } "just to be safe" silently turns off implicit return. If you add braces, you must add return.

5. Returning an object with implicit return — the parentheses trap

const makeUser = (name) => { name: name };
makeUser("Aniket"); // ❌ undefined (or syntax error)

Why it breaks: right after =>, JavaScript sees { ... } and assumes it's a function body block, not an object. Inside that assumed block, name: name looks like a label, not a key-value pair — so nothing is returned.

Fix: wrap the object in parentheses

const makeUser = (name) => ({ name: name });
makeUser("Aniket"); // { name: "Aniket" }

The ( ) tells JavaScript: "what follows is an expression (a value, like an object), not a function body." This is the standard fix — memorize it.

6. Returning early (multiple return statements)

A function can contain several return statements. Only the first one reached runs; the rest are skipped.

function checkAge(age) {
  if (age < 0)  return "Invalid age";
  if (age < 18) return "Minor";
  return "Adult";
}

checkAge(15); // "Minor" — stops here, the last line never runs

7. return with no value

function logIfPositive(n) {
  if (n < 0) return;   // exits early, gives back undefined
  console.log(n);
}

return; alone (nothing after it) just stops the function and hands back undefined. This pattern is called a guard clause — used to exit early instead of nesting more if blocks.

8. Comparison table

Explicit return Implicit return
Keyword return needed? Yes No
Braces { } needed? Yes No
Works in regular functions? Yes No — regular functions always need explicit return
Works in arrow functions? Yes Yes, only when there are no braces
Returning an object directly return { a: 1 }; ({ a: 1 }) — needs wrapping parentheses

9. Common mistakes

  1. Confusing console.log with return — logging does not send a value to the caller.
  2. Adding { } to an arrow function without adding return — silently gives undefined.
  3. Trying to implicitly return an object without wrapping it in ( ).
  4. Writing code after a return statement, expecting it to run — it's unreachable.
  5. Forgetting that a function with no return still runs completely; it just gives back undefined at the end.

10. Practice questions

Q1

function test() {
  console.log("hello");
}
const r = test();
console.log(r);

Answer: prints hello, then undefined. No return, so r is undefined.

Q2

const getUser = () => { id: 1, name: "Aniket" };
console.log(getUser());

Answer: undefined. The { } after => is read as a function body block, not an object. id: 1 is treated as a label, and nothing is returned.

Q3

const getUser = () => ({ id: 1, name: "Aniket" });
console.log(getUser());

Answer: { id: 1, name: "Aniket" }. The parentheses mark it as an object expression, so it's implicitly returned.

Q4

function checkNum(n) {
  if (n > 0) return "positive";
  if (n < 0) return "negative";
  return "zero";
}
console.log(checkNum(0));

Answer: "zero". Both if conditions are false, so execution falls through to the final return.

11. Summary (memorize this)

  • return sends a value back to the caller and stops the function immediately.
  • No return → the caller gets undefined, even though the function still ran.
  • console.log and return do different jobs — logging is not returning.
  • Explicit return: needed whenever { } is used (all regular functions, and arrow functions with braces).
  • Implicit return: only in arrow functions with no braces and a single expression.
  • Returning an object implicitly needs wrapping parentheses: () => ({ ... }).
