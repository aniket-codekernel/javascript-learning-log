Chapter 6, Section C: Arrow Functions vs Regular Functions

Syntax and this behavior, explained point by point.

1. What is this section about?

JavaScript has two main ways to write a function: the regular function (function) and the arrow function (=>). They look different, but the real difference is how they treat this.

  • Regular function: this is decided when the function is called.
  • Arrow function: this is decided where the function is written.

Everything below explains that one sentence.

2. Syntax

Regular function

function add(a, b) {
  return a + b;
}

const add2 = function (a, b) {   // function expression
  return a + b;
};

Arrow function

// full form
const add = (a, b) => {
  return a + b;
};

// implicit return: one expression, no braces, no "return" word
const add = (a, b) => a + b;

// one parameter: parentheses optional
const square = n => n * n;

// no parameters: empty parentheses required
const hi = () => console.log("hi");

Syntax rules to remember

Situation Rule
Body has braces { } You must write return yourself
Body has no braces The value is returned automatically
One parameter n => ... is allowed
Zero or 2+ parameters Parentheses are required
Returning an object directly Wrap it in parentheses: () => ({ a: 1 })

3. What is this?

  • this is a special keyword. It is not a variable you declare.
  • JavaScript sets it automatically for functions.
  • It answers the question: "which object is this function working with right now?"

Analogy: the word "I". It never changes, but who it means depends on who is speaking. this is the same: the word is fixed, but what it points to depends on who is "calling".

Why does JavaScript have this?

So one function can be shared by many objects.

function greet() {
  console.log("Hi, I am " + this.name);
}

const p1 = { name: "Aniket", greet: greet };
const p2 = { name: "Rahul",  greet: greet };

p1.greet();  // Hi, I am Aniket
p2.greet();  // Hi, I am Rahul

Write the function once, use it for any number of objects. A function does not belong to one object, so it cannot know who is using it until it is called. That is why this is decided at call time for regular functions.

4. Regular functions: dynamic this

The main rule

this = the object written immediately before the dot when the function is called.

const person = {
  name: "Aniket",
  greet: function () {
    console.log(this.name);
  }
};

person.greet();   // person is before the dot, so this = person, prints "Aniket"

Detached call

const detached = person.greet;
detached();       // nothing before the dot, so this is NOT person
  • Non-strict mode: this = the global object (window in browsers), so this.name is undefined (or "" in a browser).
  • Strict mode or modules: this = undefined, and this.name throws an error.

The function is the same in both calls. Only the call changed, and for regular functions the call decides this.

Important facts

  • The key name (greet, hello, anything) does not affect this. You just call it by that key.
  • The way you write the function in the object (greet: function(){} or shorthand greet(){}) does not affect this either.
  • Only the call matters: object.key().
  • Calling with new (constructor) sets this to the brand-new object.
  • .call(), .apply(), .bind() can set this manually (Section I).

return is unrelated to this

Job
return Sends a value out of the function
this Says who is calling the function

console.log prints without needing return. A missing return never causes this problems.

5. Arrow functions: lexical this

The main rule

An arrow function has no this of its own. It uses the this of the code around where it was written.

"Lexical" means "based on where it is written in the code."

The borrowing rule

Look outward from the arrow function until you find a regular function. Borrow that function's this. If there is none, use the top-level this.

An object { } does not count. Only functions have a this to lend.

Analogy: an arrow function has no phone. It borrows the phone of the room it was written in. Once written, it never changes rooms.

Example A: arrow directly in an object (does NOT work)

const person = {
  name: "Aniket",
  greet: () => {
    console.log(this.name);
  }
};

person.greet();   // undefined

Why:

  1. Around the arrow is the object { }. Objects give no this.
  2. Around the object is the top of the file, with no function.
  3. So the arrow uses the top-level this, which is not person.
    • Node.js: {} (empty object)
    • Browser: window
  4. this.name is not "Aniket", so the output is undefined.

The phone is not missing. It is the wrong phone.

Example B: arrow inside a regular function (WORKS)

const person = {
  name: "Aniket",
  start: function () {
    const inner = () => {
      console.log(this.name);
    };
    inner();
  }
};

person.start();   // Aniket

Why:

  1. inner is an arrow, written inside start.
  2. start is a regular function, so it has a this.
  3. start was called as person.start(), so its this = person.
  4. inner borrows it, so this.name is "Aniket".

The same arrow syntax gives a different result. What surrounds it decides.

Arrow this is fixed forever

const detachedArrow = person.greet;   // arrow from Example A
detachedArrow();                      // still undefined
  • The call is ignored by arrow functions.
  • this was settled once, at writing time.
  • .call(), .apply(), .bind() cannot change an arrow's this.

6. Why were arrow functions created? The setTimeout problem

The problem with a regular function inside

const timer = {
  seconds: 0,
  start: function () {
    setTimeout(function () {
      this.seconds++;               // wrong "this"
      console.log(this.seconds);    // NaN in a browser
    }, 1000);
  }
};
timer.start();
  • timer.start() gives start the right this (timer).
  • But the inner function is called later by JavaScript itself, with nothing before the dot.
  • So the inner function's this is not timer.

The fix: arrow function

const timer = {
  seconds: 0,
  start: function () {
    setTimeout(() => {
      this.seconds++;
      console.log(this.seconds);    // 1
    }, 1000);
  }
};
timer.start();
  • The arrow is written inside start, so it borrows start's this (= timer).
  • It doesn't care that JavaScript calls it later with nothing in front.

This is the main real-world reason arrow functions exist: callbacks inside methods keep the outer this.

7. Other differences (beyond this)

Feature Regular function Arrow function
Own this Yes (dynamic) No (lexical)
arguments object Yes No, use rest params (...args)
Use with new (constructor) Yes No, throws an error
Hoisting Declarations are fully hoisted Not hoisted (behaves like a variable)
.call/.apply/.bind change this Yes No (ignored)
Good as an object method needing this Yes No
Good as a short callback Okay Yes, best choice
Implicit return shorthand No Yes

arguments example

function regular() { console.log(arguments); }   // works
const arrow = () => { console.log(arguments); }; // error, or picks up an outer function's arguments

const arrow2 = (...args) => console.log(args);   // correct way in arrows

8. When to use which

Situation Use
Object method that needs this to be the object Regular function (or shorthand method)
Callback inside a method that needs the outer this Arrow function
Short callback like arr.map(n => n * 2) Arrow function
Constructor function (new Foo()) Regular function (or class)
Standalone helper, no this involved Either, arrow is common
Function that needs arguments Regular function, or use rest params

9. Common mistakes

  1. Arrow function as an object method that uses this. It borrows the top-level this, not the object, so you get undefined.
  2. Detaching a regular method (const x = obj.method; x();). this is lost because nothing is before the dot.
  3. Calling a method by the wrong name. You call it by the key, not by the original function's name.
  4. Thinking return affects this. They are unrelated.
  5. Thinking an object { } gives this to an arrow inside it. Only functions do.
  6. Using arguments in an arrow function. Use rest parameters.

10. Practice questions (try before reading the answers)

Q1

const car = { brand: "Tata", show: function () { console.log(this.brand); } };
car.show();

Answer: Tata. car is before the dot, so this = car.

Q2

const x = car.show;
x();

Answer: undefined. Nothing is before the dot, so this is not car. (Not because of return.)

Q3

const car = {
  brand: "Tata",
  show: function () {
    const inner = () => console.log(this.brand);
    inner();
  }
};
car.show();

Answer: Tata. inner borrows show's this, and show was called as car.show().

Q4

const car = { brand: "Tata", show: () => console.log(this.brand) };
car.show();

Answer: undefined. The arrow is directly in an object, so it uses the top-level this.

11. Summary (memorize this)

  • Regular function: this is decided by how it is called. It can change every time. Rule: object before the dot.
  • Arrow function: this is decided by where it is written. It never changes. Rule: borrow from the nearest surrounding regular function, or the top level.
  • Objects { } do not give this to arrows. Only functions do.
  • Use regular functions for object methods, arrow functions for callbacks inside them.
  • return and this are two separate things.
